# changelog 规范

版本档案放在本目录（`docs/changelog/`），每个版本一个文件。

## 文件名

`vX.Y.Z.md`，与 versionName 同步（例如 `v0.148.0.md`）。

## 每文件必须含的三节

1. **新功能**：本版新增的能力。
2. **修复**：本版修掉的问题。
3. **已知限制**：本版已知但未修的问题，如实写，不藏。

## 写作规矩

- 发版时写，不要提前编造功能清单；没验证的条目不要写进去。
- 每条一句话，说清“改了什么、用户能感知到什么”，不要堆技术细节。
- 文件头写一行版本信息：状态、日期、tag，例如：
  `状态：版本档案 ｜ 日期：2026-10-21 ｜ tag v0.148.0`
