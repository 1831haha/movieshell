# v0.189.0

两件事：换源之后，首页“继续观看”无法跳转到之前看的那个源；聚合搜索加“所有源 / 只搜当前源”开关。

## 聚合搜索范围开关

- 搜索框下方加两个小标签：“所有源”（默认，旧行为）和“只搜当前源”；选择记在设置里，重启后仍保持上次选择。
- “当前源”口径与首页一致：订阅当前源优先，其次本地 drpy、PY、PHP 规则；只搜当前源时配置里只放这一个源，订阅当前源的条目形态与全量搜索里一致，drpy、PY 用原有合成站形态。
- 切开关时如果已经搜过一个词，立即按新范围重搜，不用重新输入。
- 顺带修了一个查码时发现的旧问题：聚合搜索里的本地 drpy 条目（type=4）一直撞上 type4 PHP 分发，实际搜不出东西；本版按 key 先分流到 drpy 引擎，聚合搜索（所有源和只搜当前源）里的 drpy 才真能出结果。
- 只搜当前源且没有设置任何当前源时，搜出来是空——空结果页会明说“当前没有设置首页源”，并给“切回所有源”按钮，不会让用户对着空页猜。实现上无源时直接出空结果、不走配置加载：空配置会被站源仓库当成残缺订阅而保留旧站源列表，那样就悄悄变回全量了。
- 已知限制：PHP 规则此前不在聚合搜索里，只搜当前源且当前源是 PHP 时是本版新补的单源条目，真机要验 PHP 搜索本身是否正常出结果。

## 根因

- 历史记录 `HistoryEntry` 只有标题、地址、剧 ID 和集数，没有记当时是哪个源；播放页保存进度时也没有传源。
- 首页“继续观看”只按剧 ID 和集数进详情页，详情页只认换源后的当前源，所以旧源的剧 ID 和集数对不上，播不了或播错。

## 改法

- `HistoryEntry` 加 `sourceType`（sub/drpy/py/php）和 `sourceKey`（订阅站站点 key 或本地规则名），默认值都为空；`HistoryStore.saveProgress` 加同样两个参数，默认值为空。`Json` 已是 `ignoreUnknownKeys`，老历史读入不崩。
- 播放页进入时快照一次本会话的源类型和源 key，口径与详情页追剧一致：有订阅站上下文取订阅站，否则取当前激活的 drpy、PY、PHP 规则名；无源时为空，不冒充。退出保存进度和切地址保存上一地址进度时都传这份快照，不在退出时现取已换过的激活规则。
- 首页“继续观看”签名扩展为带源类型和源 key，卡片本身不删、不改排序；主界面进详情前按追剧同款逻辑恢复源：drpy、PY、PHP 先清订阅站上下文再激活对应规则，订阅站按 key 查到站点才设上下文。
- 旧历史（源类型和源 key 为空）和订阅站查不到时，保持当前源，不弹错、不清现有源、不丢卡片。

## 本版刻意不修的事

- 日志里 11:28 旧版 v0.172 的直播 SSL 旧崩溃、PY 直播规则 `playerContent` 缺 `ids` 的规则兼容问题、21:38 那条带分隔符的播放地址被拒，均不在本版范围，另立任务再定。

## 待真机验

- A 源看一半，换到 B 源，再点首页“继续观看”，应跳回 A 源同一集，而不是在 B 源下播错或播不了。
- 旧历史（没有源字段）点“继续观看”，仍走当前源，不弹错，卡片还在。
- 订阅站被删、站点查不到时点“继续观看”，保持当前源，不崩。
