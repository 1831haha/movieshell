# v0.216.0（2026-10-25）

全量审查报告里“崩溃与数据丢失”17 条的修复版。其中 C1/C2/C11/C17 已在 v0.215.0 推版时修掉，本版修剩下 13 条。

## 修了什么（用人话）

- **删音乐源不再留悬空**（C3）：原来先删脚本文件、再写注册表，写盘失败就剩一个指着不存在文件的源；现在先写注册表、成功再删文件，失败直接提示“删除失败，音源未改动”。
- **音乐数据读坏不再悄悄丢**（C4）：注册表、歌单、本地音乐、搜索/播放历史任一文件读坏，都会暂停写盘（防止随手加一首歌就把旧数据覆盖掉），并在音源管理页 / 音乐页顶上出一条红横幅，点“重新开始”清掉损坏文件、点“暂不处理”先放着。
- **播放历史读坏同款保护**（C5）：读坏后播新视频、删单条都不再写盘覆盖；历史页顶上同样有横幅和“重新开始”。
- **下载页“清空已完成”加确认**（C6）：原来一点就删全部已完成文件；现在先弹确认框，写明连文件一起删、不可恢复。
- **阅读器空打开不再洗进度**（C7）：退出保存沿用滚动停存的守卫——没载入完、或书是空的，不写盘。
- **换源进度钳制不断标题**（C8）：新目录变短时，进度只改下标不清标题，新标题取新目录对应章；新目录为空时不写这条进度。
- **书签/净化/统计/追更/进度加锁**（C9）：连续快点不再互相覆盖；追更 clearAll 不再绕过锁；进度 clear 走与保存同款的损坏恢复底本。
- **书架 id 不再靠 hashCode**（C10）：新 id 用源 key + 远端 id 全量拼接（只留字母数字与 - _ .，超长截断缀 hash），老 hash id 仍认，旧书不受影响；本地 TXT 导入判重从只看书名改成书名＋章节数＋首章标题三项全对。
- **已装插件表一条坏不再拖垮整张**（C12）：逐条容错，坏的单条原样留着、下次写盘带回；整张都坏时直接拒写保全原串。
- **回收站恢复不再留双份**（C13）：改名优先（同盘原子移动），改名失败回退拷贝＋删源失败撤回副本。
- **云备份摘要不成对不再锁死**（C14）：摘要重试一次，仍失败就删掉刚传的新备份（旧备份已被覆盖，删了不是回到旧版，是让下次恢复明确报“云端没有备份”而不是摘要不符卡住）；恢复时摘要不符的文案给两条路：删云端备份重传、或检查网络重试。
- **备份恢复前先落盘快照**（C15）：恢复动笔前把当前完整备份写到磁盘，成功后删掉；中途被杀/失败则留着，设置页“备份与恢复”里出现“恢复中断前的备份”入口可一键导回。
- **文件预览防越目录**（C16）：kind 收进 js/py/php/web 白名单，文件名规范化后必须落在 kind 目录内，`../`、绝对路径、符号链接跳出目录的一律按“文件不存在”处理。

## 没做的事

- restoreBookshelf/restoreMusic/restoreFollow 的“删光再重建”没有改成“先算新表再一次写盘”（需要给三个 store 新开批量替换接口，改动面大）；C15 的磁盘快照已兜住中途被杀丢数据的风险，窗口收窄但未彻底消除。
- 摘要不符仍是硬拒绝，没有加“忽略摘要恢复”按钮（可能截断的备份不拿来恢复更安全）。
- C4/C5 的“重新开始”是显式放弃损坏数据（备份本身就是坏字节，解析不回来），不是修好旧数据。
