# v0.170.0

## 备份恢复链（BackupManager / ApiSourceStore / 云同步）
- 恢复前全部校验先行：版本不对、缺 apiSources、apiSources 不是数组、任一条订阅缺名称或地址、activeRules 格式不对，统统拒绝恢复，当前数据一动不动；老版本合法备份（version=1、条目含 name/url，note/group/parentUrl 可缺）照常恢复。
- 写盘失败不再报成功：ApiSourceStore.save 改为原子写盘并返回成败；恢复写盘失败、或写后回读条数对不上，都返回失败。
- 恢复有回滚：恢复前快照当前订阅文件字节 + drpy/py 当前规则；写盘或切规则任何一步失败，文件与规则双双还原。
- 损坏的导出不再覆盖云端好备份：本地订阅文件已损坏时，本地导出与 WebDAV 上传都拒绝（返回明确原因），不再用空表覆盖。
- 本地导出写盘也改为原子写盘，写盘失败如实报错。

## JSON store 写盘原子性
- 新增共享 helper `AtomicFile`（临时文件 + fsync + 同目录改名替换），各 store 共用，不各写一套；写中途被杀只留无害 .tmp，正式文件不会是截断 JSON。
- 已接 helper 的 store：ApiSourceStore、BookmarkStore、BookshelfGroupStore、ReadingProgressStore、ReadingStatsStore、NovelUpdateStore、SearchHistoryStore、SniffPatternStore、SourceProbeStore、MusicHistoryStore、MusicStore、MusicSourceStore、NovelStore（含书架索引与章节文件）、HomeCache、SubSiteStore、BookSourceManager、PurifyRuleStore、WebSourceManager（网页站源新建）。
- 读坏保全：上述用户数据 store 解析失败时，先把原文件拷为 `<原名>.corrupt.bak` 再按空处理，旧字节留作恢复证据；"读坏了→当成空→写盘把全量数据清掉"这条链不再静默发生。首页缓存是可再生数据，只做原子写盘、不做保全。
- prefs 型核心 store：FollowStore 写盘改 commit 同步写并返回成败，follow/unfollow/markNew 写盘失败如实返回 false；HistoryStore 补 ignoreUnknownKeys（加字段不再导致旧文件读坏），解析失败原串保全到备份键。prefs 的 apply 本身是平台级原子写，文件级 helper 不适用这里。

## 首页换源胶囊
- 灰圈修复（选判定优先法，不动 contentGen）：环判定改为加载中 → 有数据（drpyReady）→ 未选源/未加载过 → 失败；切 tab 重组后 contentGen 归零、纯推荐恢复不 bump 世代时，有数据也不再判灰。
- 外圈：状态点本身不变，整个换源胶囊外加一圈状态色边框，颜色语义不变（加载中黄 / 失败红 / 完成绿，未选源/未加载过为灰）。
- 恢复分支：原选是推荐时只恢复推荐，不再悄悄进分类 1；原选分类已不在列表里时才退回第一个分类。

## 已知限制
- 备份覆盖范围仍以 ApiSourceStore 为主（订阅 + drpy/py 当前规则名），其余 store（追剧、书架、音乐、直播、插件、解析、音源等）仍不在主备份里，覆盖扩展留待后续版本。
- 本版未做写盘锁（RMW 并发丢更新）、插件安装回滚、下载/订阅/字幕等其它审计项，均未动。
- 损坏文件的 .corrupt.bak 只留一份，后一次损坏会覆盖前一次；恢复旧数据需手动把 .bak 拷回原名，应用内暂无一键恢复入口。
