# v0.225.0（2026-10-25）

搜书全链路诊断进悬浮窗：首抓、后台验证、重抓三处结果全记出来，
不再只看到最后一句“未抓到页”。

## 背景

- 224 让“搜书诊断”在悬浮窗里可见后，999 搜“我的”只剩一句
  “未抓到页”，且搜的时候没弹过验证窗口。按代码推断：首抓失败
  后走了 30 秒后台验证，后台“通过”了才没弹可见窗，但重抓还是空。
- 但这只是推断：首抓到底是 403、连接重置还是超时，后台验证是
  真拿到 cf_clearance 还是空页“通过”，重抓又是怎么空的——
  原来这三处要么只写系统 Log（悬浮窗看不见），要么根本没记。
  不把整条链的证据一次摆出来，就还是在猜。

## 改动

- gatedFetch 三处记 LogBus（悬浮窗可见，只记状态与长度，
  不记正文与 Cookie 值）：
  - 首抓空：记 httpCode（null = 没拿到 HTTP 回复，如连接重置/超时）；
  - 后台验证：记通过/失败，通过时记有无 cf_clearance、页长、Cookie 长；
  - 可见验证未通过、重抓空：各记一行与重抓 httpCode。
- BookRuleEngine 两处抓取失败日志由系统 Log 改走 LogBus，
  并带上异常类型（如连接重置还是超时），原来悬浮窗里看不见。
- 本版不改任何验证与请求行为，只补证据。下一次搜 999，
  凭这几行就能一次分清：是假通过（无 cf_clearance 的空页通过）、
  还是 POST 那条路单独被墙、还是重抓又撞上间歇性重置——
  再动手修，不再猜。
