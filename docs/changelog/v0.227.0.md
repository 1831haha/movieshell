# v0.227.0（2026-10-26）

226 装上后果然搜书通了：搜“我的”解析出 30 条——ES6 的判断是对的。
但点“加入书架”又弹“加入失败（目录拉取失败）”，这是同一类 bug 的
下一环，不是新问题。

## 真因：目录、正文、封面三处都漏了握手后重抓

- 999 这类源的详情页带 1234 门：页里有 div.title 含 1234 时，
  loginCheckJs 会 POST action=1&v=1234 握手，握手完把页换成
  “success”短串，等调用方重抓一次拿真页。
- 搜书（136 行）和发现页一直都传了重抓，所以 226 搜书通了；
  但目录、正文、封面四处调用 loginCheck 时传的都是 null——
  重抓这步被丢了，“success”短串直接被当成详情页去解析，
  章节列表永远是空，入架两次重试都空，于是弹目录拉取失败。
- 详情页请求本身是 200，不是墙、不是 403、不是规则写错；
  悬浮窗里只有 GET 200 的行、没有目录解析的行，所以之前
  看不出来——本版目录加了一行诊断。

## 改动

- 目录、正文、封面：loginCheck 全部补上重抓（重抓原页地址，
  与搜书/发现页同一写法）；握手 Cookie 走共用网络库，重抓
  拿到的是握手后的真页。
- 目录诊断进悬浮窗：详情长、握手后长、解析出几章一行记清，
  下次再空直接分清是没拿到页、握手换了页、还是规则没命中。
- 搜书结果卡片瘦身：封面 56×76→48×64、内边距 14→10dp、
  行距 10→8dp，单卡约 104→84dp，一屏多看两本左右；
  书名最多显示两行，长书名不断尾。
- 书源管理四个导入入口并成一个：标题行末尾一个“导入书源”
  钮，点开弹窗再选粘贴/URL/文件/本地 PY，原四路动作原样
  接线；原来四个大钮占的一行省掉。
- 书源管理头部再压一压：标题行、说明行、按钮行、搜索行
  之间的空隙收紧，列表往上提约 66dp。
