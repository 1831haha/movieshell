# v0.224.0（2026-10-25）

搜书诊断日志改走应用内日志总线，悬浮窗里终于能看见。

## 背景

- v0.223.0 加的“搜书诊断”日志用的是系统 Log，只进 logcat；
  而 App 内悬浮日志窗只订阅 LogBus 环形缓冲，所以 223 上搜 999
  时诊断行从来没在悬浮窗里出现过——不是搜索没跑，是日志走错了道。
- 表现为：悬浮窗里只有 CmsApi（它走 LogBus）的请求行，
  NovelSourceEngine 的诊断行一条都没有。

## 改动

- NovelSourceEngine 全部 6 处搜书相关日志改走 LogBus：
  搜书诊断（未抓到页、校验前后长度与解析条数）、JSON 搜索失败、
  PY 书源搜索/目录/正文失败（失败原因拼进消息，LogBus 无
  Throwable 重载）。LogBus 本身同时写一份到 logcat，原有
  logcat 可见性不变。
- 装上 224 后再搜一次 999，悬浮窗里就能看到“搜书诊断”那行，
  凭校验前长/后长/条数即可分清是请求问题、握手改写了页，
  还是解析出空。
