# v0.160.0

## 改动
- 直播频道卡片压紧 + 源行上移：频道卡片上下内边距 8→4dp、台标 36→30dp、直播徽标和星标间距收紧；同名源（源1/源2）从右列删掉，移到播放器下方一行，卡片右上角只留星标；列表改为分组 + 频道两列，频道列扩满。
- 选中状态不再丢：选中频道和按台名选的源放内存单例，切 tab 离页重组、聚合刷新都不回首台、不回源1；中列每台只显示一条，显示该台上次选的源；同台重复点不重建播放器。
- 直播 8 秒无画面切源：自起播以来 8 秒内从未真正播过，就走原有自动切同名源（不弹错误框）；播过后用户手动暂停不触发，换地址后计时重置。内核不动。
- 频道自带 UA 透传：插件 lives 里 ua 字段有值时才传给播放器，无值时不编 UA/Referer。

## 说明与已知限制（对 TRAE 三点的核对，不照单全抄）
- 聚合刷新重置：原代码里聚合刷新只在 selected==null 时才取首台，真正丢状态的是切 tab 离页重组（remember 丢失），本版用单例修的是后者；2 秒连播 5 台是不同台连点，不是同台重复点，同台重复点本版已拦。
- 黑屏 header：Media3 播放本来就带默认 UA，不是裸请求；cctv-live 目前 ua 为空，所以本版的 UA 透传对 CCTV1 不起作用，不编一个 txiptv 的 Referer 去猜。实测：112.27.5.218 的 0001_1.m3u8 返回 200 且是有效 m3u8（5 个 5 秒 ts 段），183.223.157.33 同地址无回包，不是“返回 200 但内容为空”；源2 在手机上出不出画面，仍需在 160 上点源行源2、等 20 秒实测。
- 本版包含 159 的内容：详情卡标题在上、下面左边集数线路、右边演员简介；直播按台名记源。159 云构建因 Chaquopy 装 pycryptodome 时连 chaquo.com 超时失败、未交付，本版直接取代 159，不再单独重跑 159。
