# v0.294.17

修复音乐「切歌逻辑不对，返回逻辑也不对」。

## 返回
- 根因：迷你条、通知栏、音源管理页上的迷你条都直接 `navigate("music_player")`，无 singleTop、不查栈——双击迷你条、播放页里点通知、播放页→换源→管理音源→再点迷你条，每次都再压一层播放页，返回要按两三次才回到音乐主界面；返回箭头连点会多弹。
- 新 `MusicPlayerNav.kt`：`openMusicPlayer()`（已在播放页不动作 / 栈里已有则弹回该层 / 否则 singleTop 新开）、`closeMusicPlayer()`（仅当前是播放页才弹一次）；通知路由同走此入口。
- 音乐页歌单标题改 rememberSaveable，返回后不丢。

## 切歌
- 显示态立即切到新曲 + 转圈，旧曲立即停（原来地址到手前界面不变，日志里用户连点 4 次下一首、同一行连点十来次）。
- 下一首/上一首 250ms 防抖；被取消的 LX 解析立即终止 isolate（原来 JS Promise 链继续跑，十来条链并发抢网络）。
- 点正在播/解析中的同一首不重来；上一首已播 >3 秒回到开头；随机模式上一首走历史。
- 解析失败或流出错（ERROR_CODE_IO_BAD_HTTP_STATUS）：先重解析一次；下一首/上一首/自动连播方向上自动跳过，最多试一圈；点名歌曲停下提示。出错后点播放键会重新解析（原来 IDLE 下 play() 无效）。
- 单曲循环/单首队列播完原地 seek 0，不再重解析。
- 通知栏上下首：补 seekToNextMediaItem/seekToPreviousMediaItem 与 COMMAND_SEEK_TO_NEXT/PREVIOUS。
- 息屏自动下一首：解析期 45s PARTIAL_WAKE_LOCK，ExoPlayer WAKE_MODE_NETWORK（日志里息屏解析卡了 95 秒/174 秒）。
- 切换播放模式给 toast。
- 新增单测 MusicQueueLogicTest、MusicPlayerNavTest。
- 版本 0.294.17 / versionCode 379。
