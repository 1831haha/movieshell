# v0.173.0

本版只修一件事：直播刷新撞上死源就闪退。

## 闪退根因（2026-10-23 11:12 用户日志，v0.172.0）

- 堆栈：`LiveStore.downloadText` 抛 `IllegalStateException: HTTP 404`，
  经 `LiveStore.refresh` 一路穿出，撞上直播订阅管理页没包 runCatching
  的 `scope.launch`（主线程协程），未捕获异常直接闪退。
- 旧代码的缺口：`refresh` 里 `withTimeoutOrNull(15_000)` 只拦超时，
  不拦下载抛出的 HTTP 非 2xx、空响应、断连异常；本地文件那条
  走了 runCatching，网络订阅那条没走。
- 连坐效应：一个源死掉，整次刷新抛掉，其余正常源的频道也出不来。

## 修法

- `LiveStore.refresh`：每个网络订阅的下载单独 try/catch，失败只记入
  未解析清单并继续下一个源，绝不因单个源抛掉整次刷新。
  失败原因写进清单，例如“热舞直播（HTTP 404）”，主直播页的
  doRefresh 本来就会把这份清单弹出来，不再静默。
- 协程取消原样抛出，不当成单源失败吞掉。
- 插件 JSON 文件单个读不出也只跳过该文件，不让 refresh 整体抛。
- 只改 `LiveStore.kt` 这一处根因，管理页那 5 处裸 launch 不用逐个
  打补丁：refresh 本身不再因单源失败抛，裸 launch 也就撞不上这
  类闪退。

## 已知：死源本身没复活

- 本机 2026-10-23 午间复测 172 那 11 条：热舞直播、YueChan Global
  回 404，推荐直播回 530，长苏回 403、蓝天白云回 401，其余有
  200 也有连不上的——手机网络和本机不一样，具体哪条在你手机上
  回 404 以修复后的提示为准。
- 修后做法：装上新版，进直播订阅管理，提示里点名哪个源失败就删
  哪个；删后 App 不自动补回。但注意：如果你自己再点一键导入，
  被删的源会被当成“缺失”补回来，所以对已知死源别再点一键导入。

## 待真机验

- 含死源的订阅列表刷新不再闪退，其余正常源频道正常出，提示里
  点名失败源及原因（HTTP 404 等）。
- 删掉提示里的死源后刷新，提示消失。
