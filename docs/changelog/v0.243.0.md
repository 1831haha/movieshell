# v0.243.0（2026-10-26）

两处返回落点修复：找书界面按系统返回先回书架；滚动模式
手指下拉越界回上一章落末页。

## 找书返回

找书界面按系统返回，先回书架，不再直接落到首页。

## 根因

找书不是导航路由，只是书架内的一个状态（`searching`）：
点书架顶栏的放大镜进找书，界面换成“找书”行 + 内嵌搜索
结果，但导航栈里并没有多一层。之前这层状态没有拦截系统
返回，返回直接 pop 掉书架路由，落到导航栈底的首页——
右上角“取消”能回书架，系统返回却不能，两边行为不一致。

## 改动

- 书架屏加 `BackHandler(enabled = searching)`：找书态下按
  系统返回，只把 `searching` 置回 false，回到书架列表，
  与点“取消”完全同义；键盘打开时先收键盘，再按才回书架
  （系统默认行为）。
- 非找书态的返回逻辑一个没动：书架本身按返回仍是原来的
  路由行为；书架多选管理、菜单、弹窗等其他状态不在这版
  动。

## 核对

- 改动只涉及 BookshelfScreen 一个文件（1 个 import + 1 处
  拦截），双自查（import、括号）全绿。
- 搜索框、结果列表、加入书架、点卡片进详情的逻辑一个没动。

## 滚动模式下拉回上一章落末页（GPT 修复，助手审过）

- 现象：第 2 章章首继续下拉，该回第 1 章末页，实际落到
  第 1 章开头；241 修的是翻页模式，滚动模式手指越界这一路
  仍在犯。
- 根因：下拉越界时手势还没结束就切章，恢复效果刚滑到底
  就被旧章未结束的手势拖回章首——与 241 翻页模式手势回弹
  把页码拽回 0 是同类问题，只是发生在滚动模式。
- 改法：下拉越界分支先不等切章，等滚动完全停稳（手指离开
  且惯性滑停）再 jumpTo 上一章末页哨兵；恢复效果与末页哨兵
  原样接管。只动下拉这一路，上滑进下一章与翻页模式一个没动。
- 审过：scope 与 withFrameNanos 在文件里已有（153 行、68 行
  import），无需新 import；手势结束即触发，不会卡住；切章后
  新手势重新从 boundaryJumped=false 计，不会连跳。

## 落点守门统一到所有切章方式（用户要求：上下滑、左右翻、
松手惯性、按钮/音量键都走同一逻辑）

- 241 的守门只守了翻页模式，滚动模式恢复效果没有这一条：
  音量键/按钮在惯性未停时切章，同样会被拖回章首；只修
  下拉分支堵不住其他路。
- 改法：恢复效果的守门改成两种模式通用——切章落点一律等
  本模式滚动停稳（拖动 + 惯性都结束）再落；scrollState 的
  停稳信号已进效果 key，停稳时重跑补落点，不会卡住；无手势
  的按钮/音量键路径立即落，原样不动。
- 这样上下滚动、左右翻页、松手后的惯性回弹、按钮与音量键
  切章，全都经过同一个守门；下拉分支的“等停稳再切章”与这
  个守门是两层，互不冲突。
- 另：全仓查过，App 里没有自动翻页功能；“放着翻页”若指
  松手后靠惯性自己翻过去，已在守门内，若指别的，跟我说一声。
