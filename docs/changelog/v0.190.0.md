# v0.190.0

只做一件事：聚合搜索的“所有源”改成搜遍全部本地规则文件。

## 根因

- 此前“所有源”里本地规则只有两条合成站：drpy:active、py:active，走的都是当前激活规则的引擎。手机里有多个 PY 规则时，所有源也只搜激活的那一个，189 收到反馈的日志里就是这样：先只搜 py:Pandalive.py，换规则后只搜 py:juok.py。
- PHP 规则此前根本不在聚合搜索里。

## 改法

- 所有源的配置改成按规则逐条拼：订阅站展开照旧；drpy、PY、PHP 各按规则列表（xiaying/js/、xiaying/py/、xiaying/php/t4_demo/）逐条加一个站，只含未被禁用的规则；激活规则不再单列一条，否则同一规则会被搜两次、出两个同名分组。
- 逐条的引擎按规则文件取，不依赖当前激活规则：drpy 走引擎池（SubSiteEngines 按 local:drpy: key 取文件），PY 按规则路径直接调，PHP 按 php: key 取脚本名走 CLI。drpy 的 type=4 会撞 type4 PHP 分发，已在搜索分发里按 local:drpy: key 先行分流到 drpy 引擎（189 修 drpy:active 的同款坑）。
- 点本地规则的搜索结果时，先把该规则切成当前激活规则再进详情：详情、播放、追剧、继续观看全部走现成的“当前激活规则”链路，不另起一套分发；不切的话，点非激活规则的结果会错走到当前激活规则上出详情、播错片。
- “只搜当前源”不动：仍只搜首页当前源一条（订阅当前源 > drpy > PY > PHP），无当前源时仍直接出空结果、不回退全量。

## 已知限制与待真机验

- 本地规则多时，所有源一次要并发搜很多站：搜索页原有并发限流（4 路）和单源 15 秒超时仍在，规则越多等得越久，慢源仍会进失败汇总；本版不改限流口径。
- 待真机验：所有源下，多个 PY 规则是否各出一个分组、结果是否按规则分开；点非激活规则的结果，进详情、播放、追剧后是否都是该规则（而不是之前激活的规则）；drpy、PHP 规则在所有源里是否同样出结果；被禁用的规则是否不出现。
