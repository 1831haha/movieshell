# v0.226.0（2026-10-26）

999 搜书真因找到：搜索地址的 JS 根本没求值成功，请求连手机都没出。

## 真因（225 全链路日志一次摆出来的证据）

- 搜“我的”时悬浮窗里是这样一串：
  首抓空 httpCode=null、后台验证通过 cf=false htmlLen=46742
  cookieLen=0、重抓空 httpCode=null、未抓到页；且两次抓取失败
  都是 `IllegalArgumentException：no scheme was found for <js>...`。
- 翻译：传给网络库的根本不是网址，而是整段没求值的 `<js>` 原文，
  请求在手机里就炸了，根本没发出去——之前猜的墙、403、验证，
  对搜书这条路全是错的，墙只存在于发现/书库那条路。
- 链条：搜索地址 JS 求值失败 → 旧逻辑静默回退原串 → 网络库
  以“无 scheme”炸掉 → 首抓空 → 30 秒后台验证（首页 46KB
  正常页、无挑战标记，于是“通过”但 Cookie 为空）→ 重抓同样炸掉。
- 求值失败本身也只记系统 Log，悬浮窗看不见，所以 224 之前
  连“求值失败”这句都看不到。

## 改动

- Rhino 改走 ES6：规则里 `let` 这类现代写法在默认语言版本下
  可能直接语法错误、整段求值失败；ES6 下求值，旧写法不受影响。
- JS 求值失败记进悬浮窗（LogBus），不再只写系统 Log。
- 搜索地址求值失败直接跳过本次搜索并记一行，不再拿原串
  去撞网络库、白白走 30 秒验证；登录后重抓同样判空。
- 本版若仍失败，悬浮窗里会直接印出 JS 报错原文，
  下一步不用再猜。
