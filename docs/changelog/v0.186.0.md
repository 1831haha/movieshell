# v0.186.0

审计前 10 组优化（审计报告见 `audit-full-v186.md`，只做第 4 节前 10 组，其余 62 项不在本版）。未推送前请勿把本版当作已编译验证：本地无编译器，双自查已绿，云构建仍需兜底。

## 1. V8 并发与超时（H01+H02）

- `ensureSession` 加 Mutex 单例化：并发调用排队复用先建成者，不再各自 bootstrap 出两个会话；建会话期间换规则或 release，后建好的会话在发布前 close 后丢弃。
- `eval` 加串行 Mutex：同一会话一次只跑一个 eval；超时只标记会话失效并在 1 秒宽限期后延迟回收，不再瞬间 closeIsolate 连坐杀死同 isolate 上其他在途 eval。
- `connect` 与 `bootstrap` 加与 eval 同档的 15 秒超时：connect 超时只返回 null，不清共享 future（绑定后台继续，后来者复用同一 future，不会重建连接触发“Binding to already bound service”）；bootstrap 每条脚本同档超时，超时置 lastError、直接 closeIsolate、返回 false。
- 引擎池加在途计数：淘汰只选在途为 0 的引擎并 release，在途不为 0 的绝不 release；全部在途时记 warning 后暂超上限建新引擎（理论上不可达，纯防御）。

## 2. 嗅探原始请求头（H05）

- `SniffCandidate` 加 `headers` 字段；`shouldInterceptRequest` 与 Service Worker 拦截命中 DIRECT 时原样存 `requestHeaders`，不现拼 Referer/UA/Cookie 覆盖。
- `finishPyPlay` 解析出 direct 后、返回前对 direct 再 put 一次原规则头，`take(direct)` 能命中。
- `playCandidate` 的 view==null 分支不再直接播，改为先走一次带空头集合的结算探测，硬拒绝则不播并 Toast“该地址返回的是网页不是视频流，已拦截”；view!=null 分支保留现拼头逻辑，拦截原始头优先。

## 3. 读-改-写加锁与写盘返回值（H07+L25 前半）

- `AtomicFile` 的 `.tmp` 改为唯一后缀名（UUID），两线程同写一 store 时各写各的 tmp、互不截断；renameTo 与 `.corrupt.bak` 语义未变。
- Follow、书架分组、音乐、音乐音源、音乐历史 5 个 store 各加一把锁（suspend 用 Mutex、非 suspend 用 synchronized，未为加锁把公开函数改成 suspend）；Follow 只锁 6 个读-改-写（follow/unfollow/markWatched/markNew/markFinished/clearNew），纯读与单值写不重复加锁。
- 写盘 helper 统一返回 Boolean 并记日志；已有 Boolean 返回的公开函数现如实透传失败（歌单改名/加歌失败返回 false、创建失败返回 null、音源导入失败返回 null 等），调用方忽略返回值在 Kotlin 里合法。
- 延期：Unit 返回的写盘（markWatched、本地音乐增删、歌单编辑、历史记录、分组改名/删除等）失败时目前只有 LogBus 日志、无用户可见提示——数据层 6 个文件内无 Toast 模式且写盘在 IO 线程，不宜在数据层新起 Toast，需在 UI 文件侧接返回值或提示通道，后续再补。

## 4. 损坏按空处理护栏（H08）

- `ServicePluginManager.saveRegistry` 改走 `AtomicFile`（复用唯一后缀 tmp + fsync + 改名替换）；签名由 Unit 改为 Boolean（私有函数，全仓无外部引用，内部调用点忽略返回值可正常编译）。
- `loadRegistry` 解析失败时保全为 `server_plugins_registry.json.corrupt.bak`、置损坏标记、记 LogBus 警告，仍返回空表供只读查询使用（不崩）；损坏后写空表被拒绝，损坏后写非空表允许替换（避免损坏态下永远无法安装/保存新服务而卡死）；逐个卸载的合法清空（每步先成功加载）不会被拦。
- 遗留：损坏后服务页仍显示空列表，应用内无一键恢复入口，恢复需手动处理 `.corrupt.bak`；`preserveCorrupt` 仍是单份备份，后一次损坏覆盖前一次。

## 5. 换内核与重试链（H06+M04+M05+M06+M07）

- 换内核三步固定：旧引擎位置 → stop → 改覆盖 → 新引擎 play(pos)，自动与手动同顺序；修掉了自动分支先 stop+改覆盖、再读新引擎位置（0）的错误顺序。
- `LaunchedEffect(playUrl)` 先保存进度（此时位置仍按覆盖引擎路由）再清覆盖、清 triedEngines 与 fallback 记账、重置同内核次数。
- 初始起播失败走完整自动链（同内核重拉 → 换内核 → 换线路），耗尽才弹错误对话框；直播耗尽后仍经原 errorMsg 效应走 onLiveError；磁力分支仍走原服务缺失对话框（磁力不能喂 EngineHost，不进此链）；8 秒直播 watchdog 未动。
- 同内核重拉不跳步：起播提交失败也计一次同内核重试，耗尽同内核 2 次再换内核、再耗尽才换线路。
- 硬解分支：取断点 → 显式停 ExoPlayer → 记入已试 Media3 → 改覆盖 → libmpv 起播；`decoderFallbackDone` 不再每次 play() 重置，改为按地址重置；libmpv 再失败后不再切回已试过的 Media3。
- RTMP/RTP：自动链里目标为 Media3 即视为不可用、直接落到换线路，与 EngineHost 强制 libmpv 路由一致；断点取自改覆盖前的旧引擎位置。手动切 Media3 播 RTMP 仍会被 EngineHost 既有强制路由改回 libmpv，本版只修自动链判定，手动路径如需一并拦截需另行定性。

## 6. 详情选集（M01+M02）

- 第二分支 chip：先置选中态，再取已解析的真实选集，取到则复用第一分支同一播放入口，取不到则 Toast“该源未返回可播地址”，不编造地址；死代码 `playLabel` 已删（删除前全仓仅 1 处定义、零处使用）。
- `selectedLine` / `selectedEpisode` 提升为 `rememberSaveable`；`embeddedUrl` 刻意未提升，避免进程重建后直接挂载播放器等于自动起播。
- 保留说明：实测读码后，第二分支在现行代码下实际不可达（`vod.episodes` 来源就是 `episodes.size`，`lineEpisodes` 为空时 `vod.episodes` 为 0，会落入“暂无可播放剧集”），本次改动是防御性的；若要让该分支真正可达，需另立任务先定“总集数从哪里来”，本版未改分支条件与 `vod.episodes` 推导。

## 7. 备份、云同步、WebDAV（H10+H11+H12）

- 备份新增追剧、书架（含正文+分组+进度+书签）、音乐（本地+收藏+歌单）、直播（订阅+手动+收藏+全局节目单地址）四个独立段，不混进主 `apiSources` 结构；老备份（无新段）只恢复主段；校验先行、写盘回读比对、双回滚口径不变并扩到新段；文案明确写“不含插件、下载、播放历史与设置”，无“全量备份”宣称。仍未进备份：插件、下载、播放历史、各项设置。
- 恢复近似项：追剧 updatedAt/集数变化计时、书架 addedAt、歌单 id/创建时间、书架分组 id 在恢复时重算，条目内容与归属不变；分组名恢复时截断到 12 字；同章多条书签只留最新一条。直播手动频道与收藏无公开读接口，按 `LiveStore` 落盘键直读 `live_prefs`，键名须与 LiveStore 同步改。
- 云同步：上传前本地算 SHA-256，随文件存为 sidecar `movieshell_backup.json.sha256`；下载后比对，对不上直接拒绝恢复；无 sidecar 的老备份放行但记警告日志；sidecar 读取失败则拒绝恢复。上传前 propfind 取远端 mtime，与本地 last_sync_ms 比对，远端更新且未勾选强制时返回冲突，设置页用已有 TechDialog 弹确认，“仍要上传”才强制上传；恢复是用户显式点按的动作，恢复侧不设冲突门。
- 配置页 http：https 直接放行；http 须同时满足用户勾选“我知道风险”且 host 为局域网地址，否则拒绝保存；`test` / `backup` / `restore` 每次都重校验已存配置（此前已存的 http 配置现在会被挡住，需用户重新勾选确认）。
- 延期：WebDAV 密码迁 `EncryptedSharedPreferences` 延期——全仓无该依赖，任务禁改 build.gradle.kts 且禁凭空加未验证依赖，密码仍存普通 `cloud_sync_prefs`，已在 CloudSyncManager 头注释写明延期原因；未动 MD5 信任锚。

## 8. 插件四分支与解压上限（H13+H14+checkManifest/isNewer+M22）

- source/env/player/subtitle 四分支统一 staging+swap：因规则目录、pylibs、mpv-libs、subtitle 目录是多插件共享目录，整目录替换会删掉别的插件文件，故新增 `swapFileSet()` 做“按本插件文件集合换入”（先把将被覆盖或删除的旧文件搬进同父目录备份目录，再把暂存文件搬入，成功删备份与暂存；失败删已搬入的新文件、从备份还原；注册表仍在整批成功后才写）；source 换版删掉的规则按旧版注册表记录一并删除，不再残留；空包判定提前到换入之前；subtitle 的 `SubtitlePluginLoader.reset()` 只在换入成功后执行。
- 解压上限：条目数上限 2000（另有总条目数前置检查，超限在写盘前拒绝）、解压后字节数上限 500MB，超限抛异常并清暂存目录；`verifyFullManifest` 流式哈希前也加了条目数检查。
- 下载截断：超市场标注大小的 120% 即截断（市场 size 是元数据、可能滞后于包体重建，按等值卡死会误杀合法更新）；`totalHint <= 0` 时沿用旧口径不限流。
- `checkManifest` 解析失败改为拒绝安装（抛异常，调用链已有捕获并记 LogBus.e 且返回“安装失败：…”Toast）；`isNewer` 先剥 v/V 前缀再分段比对。
- 旧格式服务插件要求 `files` 清单、无清单一律拒绝（有意 breaking：无清单的存量服务包以后无法更新，须先给包补清单；暂存后的主脚本签名复核仍在；市场包 MD5 未动、未换 SHA-256 冒充信任锚，签名公钥仍是产品决策）。

## 9. 小说簇（H09+M16+M17+M26+M27）

- `updateSource` 先查索引再写章节：索引不存在直接返回 false，章节文件一动不动；存在时才走旧的正文 graft + 写章节 + 写索引。
- 抽 `deleteNovelCascade` 单一入口（NovelStore 内，紧贴 `removeNovel` 之后）：本体删除失败直接返回 false，不碰其余项；成功后依次清进度、逐条清书签、清分组、清追更角标；搜索页与书架页（单删与批量删）都改调它，两处对话框文案统一为“将从书架移除，阅读进度、书签与追更标记也会清除。”
- 追更：`updateSource` 为 false 时返回 Failed，不写角标、不弹通知；书架手动检查全失败时 Toast“检查失败，稍后再试”，部分失败时 Toast“已检查，N 本检查失败”；Worker 可查书全部失败时返回 `Result.retry()`，不再恒返回 success。
- PY 书源：导入先写带随机串的 `.tmp`、头 8KB 含 `bookSearch` 才改名正式 `.py`，校验/改名失败均删 tmp；`load` 做 `bookSearch` 存在性过滤；`remove` 文件存在但删除失败时直接返回 false，不清启用标记；`BookSourceManager` 加锁且 `save` 返回 Boolean，写盘失败时各公开函数把内存回滚旧值。
- 书源管理页提示补齐：导入/恢复/删除的写盘失败与“没有识别出书源 / 已存在”区分提示，失败文案一律含“保存失败”；粘贴/文件导入过去把“全已存在”误报为“没有识别出书源”，现改为“书源已存在，无需重复导入”。残留缺口：两处 setEnabled 均无返回值，写盘失败时只静默回滚、开关视觉上弹回，无任何提示；要补需改管理器签名，本版未做。

## 10. 删除、下载、字幕（M20+M19+M18+M21）

- 删源/删订阅统一跑文件 + 禁用态 + 探活记录 + 置顶 + active 五项清理：本地删源新增禁用态与探活清理；删订阅 `removeCache` 扩展为五项（新增 drpy/py 本地文件、按 subId_ 前缀扫 js/subs 与 py/subs、按 expandSite 原逻辑重建的 spider ext 文件；探活一次清掉订阅本身与各子站，只写盘一次）；订阅规则文件是直接删除而非进回收站（TrashStore 只记订阅元数据），恢复订阅后刷新会重下；共享的 spider jar 多订阅可共用，故意不删。
- DONE 校验：进入下载页时对 DONE 做一次存在性扫描，localPath 为空或文件不存在即降级为 FAILED、error 写“本地文件已丢失”，不删记录，降级条数用 Toast 报出；只做下载页一处，不在启动时重复做；m3u8 只剩 index 但分片被删的情况本次测不出来，属已知边界。
- 字幕/片头/片尾 key：改为 `sourceKey + "|" + vodId + "|" + episodeIndex`，播放页 10 处调用点全部切到新签名（字幕读、片头读、片尾读、字幕对话框初值与保存、SkipSettingsDialog 内外）；sourceKey 来源为进入播放页时 remember 快照的 `DetailSiteHolder.site?.key ?: Drpy/Py/Php activeRuleName()`（全空则为 null，不用显示名或 vodId 冒充），集数每次现取 `PlaySession.episodeIndex`；新 getter 首次读到某（源，剧，集）时把旧 key 值复制到新 key，旧 key 保留不删；旧 key 清理入口 `clearLegacyPerShowKeys` 已提供但未接入设置页（不自动删用户现有设置，需设置页接清理动作并说明条数后再调）。
- 订阅修复：两处 finally 无条件置标记已删，改为 try 末尾成功时才置，catch 只记日志、不置标记，下次启动/刷新可重试；`repairOnUpgrade` 空缓存提前 return 会漏标记，已改为直落到底统一置标记（空缓存即无事可修，算成功）。残留口径：`saveAll()` 内部自己吞异常，写盘静默失败时仍会被当成功置标记，这是 saveAll 自身的口径，本版未扩大改动。

## 本版未做（明确）

- 其余 62 项不在本版；不做签名验签、不恢复收藏、不编造“4K超清/无广直连”标签、不做小说语音朗读、不绕 VIP/DRM、不新开端口、不大挪移 player/ 与 HistoryStore。
- WebDAV 密码加密、Unit 返回写盘的 UI 提示、setEnabled 写盘失败提示、在线字幕详情页入口的集数穿透、旧字幕 key 的设置页清理入口，见上文各节延期说明。
- 在线字幕详情页入口集数不确定性：对话框只传 vodId、不带集数，Kit 内用 `PlaySession.episodeIndex` 现值——播放页内下载时就是当前集，详情页内下载时是自动播放已起播的那集，尚未起播或已退出嵌入播放器时只能落到初值集；彻底修法是把 sourceKey + episodeIndex 穿过对话框（需改对话框文件 + 详情页调用点），另起一波，不要在本版硬凑。
- 进程死亡恢复是理论缺口：`DetailSiteHolder` 是内存单例，进程死后恢复播放页时订阅站 key 会丢（回落为空源），该集此前按订阅站 key 存的值读不到，但会从旧 key 迁移一次旧的按剧值，不会空白；播放页进程恢复本身已是残缺态，属可接受边界。
