# v0.191.0

只做两件事：聚合搜索逐步显示；只搜当前源搜完为空时说清“搜过、确实 0 条”。

## 根因

- 旧链路是 `searchAll` 用 `awaitAll` 等全部源跑完才一次性返回，`SearchViewModel` 拿到结果前分组一直是 null，搜索页只能干放骨架屏。本轮日志就是实证：搜“手”时日志里 08:05 前后已有几十个源回了结果（275听书 50 条、8j 40 条、橘汁4K 29 条等），页面却还停在“聚合搜索中…”的骨架屏上。
- 190 起所有源要搜 150+ 个本地规则，4 路并发、单源 15 秒超时，全跑完要几分钟——不等全部跑完就一个都看不到，这个等待在 190 之前（源少）不明显，190 之后成了主问题。
- 当前源那张图不是“没搜”：日志里 08:06:11、08:06:25 两次 `search site=py:6v.py` 都跑过，“我的”“手”都返回 0 条；所有源那轮里 6v 也是 0 条。是该规则本身对这两个词没结果，不是只搜当前源没发请求。空结果页此前没把这点说清，用户只能猜。

## 改法

- `SiteRepository` 把单源搜索抽成 `searchOneSite`（searchAll 与新流式共用，不各写一份），新增 `searchAllFlow`：每源一跑完、有结果就发出一个分组，调用方先到先显示；失败汇总仍在全部跑完后（joinAll 后）才记，搜中途不给半截失败数；取消语义与旧 searchAll 同款（调用方取消透传、不记失败）。
- `SearchViewModel` 改流式累积：分组一到就追加进列表，不等全部；切开关、换词时旧搜索取消、新搜索先清列表再重搜，半截结果不会串到下一轮。
- `SearchScreen`：骨架屏只在“一个分组都还没到”时出现；一有分组就显示分组，页顶写“还在搜…”，页脚写“还在搜其他源，有结果会陆续出现…”；搜完且空才进空结果页。只搜当前源搜完为空时，空页多一行“只搜当前源 xxx，已搜完，确实没有结果”。
- 演员作品页不动：它仍用一次性 `searchAll`（跨源去重需要全量、按原顺序取首个）。

## 行为变化（用户须知）

- 所有源的分组不再按源列表原顺序排，改按先到先出：哪个源先回结果，哪个分组先出现。这是流式显示的代价。
- 并发限流（4 路）和单源 15 秒超时没动：源多时全部搜完仍要几分钟，区别只是不用干等到最后才看到第一批结果。
- 本轮日志里另有两处与本次无关、未动：PHP 4 条失败是因为这次是卸载重装后首次启动、php 插件还没装回（日志原话“服务/插件 php 未安装”），装回后才有 PHP 结果；个别 drpy 规则 0 条是老同步写法未 await / 对方 403，与搜索显示无关。

## 已知限制与待真机验

- 待真机验：搜“手”时第一批分组是不是几秒内就出现、不用等到最后；搜中途点已出现的分组进详情、播放是否正常（搜本身是否继续跑）；搜完后页顶“还在搜…”是否落下、失败汇总是否正常出现；只搜当前源搜“我的”空页是否多出“已搜完”那行；切开关、换词时旧的半截结果是否不串到新一轮。
